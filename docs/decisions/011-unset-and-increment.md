# ADR 011 — Optional-field removal and numeric increments

## Decision

`$unset` and `$inc` are supported by `updateOne`, `updateMany`, `findOneAndUpdate`, and both update entries in `bulkWrite`. They share the existing typed paths, runtime preflight, immutable-field protection, conflict checks, and generated `updatedAt` behavior.

## Removal

`$unset` accepts optional fields and the native driver's markers `1`, `true`, or `''`. Use `1` in application code. Required fields cannot be removed: a default makes a field optional on insertion, but does not make it optional in storage. Nullable fields remain required unless also marked `.optional()`.

Optional objects and arrays can be removed as complete values, even if their ordinary children are required. Immutable or generated descendants prevent removal of their container, including through arrays and beyond the dot-path depth limit. Direct writes to immutable/generated fields, through immutable ancestors, or to `_id` remain rejected.

Removal never invokes a codec, validates a replacement value, or restores a default. Optional encrypted fields are therefore removable without encryption/decryption. Removing a missing field follows MongoDB's [no-op behavior](https://www.mongodb.com/docs/manual/reference/operator/update/unset/); Mica still includes its generated `updatedAt` assignment.

## Increments

`$inc` accepts finite JavaScript numeric deltas for writable `number()` fields without codecs. Metadata-only custom number types retain this capability. Codec-backed numbers are rejected even when their application and storage types are both `number`: an encoded representation need not preserve arithmetic. The codec capability is retained through field modifiers and metadata-only wrappers at the type level.

Integer fields require integer deltas. Positive, negative, and zero deltas are supported. Bounds such as `.min()` and `.max()` describe the resulting field value, not the delta. Mica does not read before incrementing, so those result constraints require an installed MongoDB validator generated by `jsonSchema(schema)`, configured to reject invalid writes. Mica does not install validators automatically. Client checks on the operand cannot guarantee that the stored result satisfies every constraint or avoids overflow.

MongoDB performs the increment atomically within each document. A missing numeric field is created with the delta, without applying its Mica default; incrementing an existing `null` fails with the native server error. Optional and nullable numeric fields remain eligible at the type level because the actual stored value determines this outcome. See the [MongoDB `$inc` contract](https://www.mongodb.com/docs/manual/reference/operator/update/inc/).

## Combinations and limits

Sibling paths can be updated together using `$set`, `$push`, `$unset`, and `$inc`. Equal paths and ancestor/descendant overlaps across operators reject before any command is sent. The same preflight runs for every bulk entry before sending the batch, including unordered batches. Server errors still retain native partial-write semantics for multi-document and bulk operations.

Later decisions add scalar [array operations](013-array-operators.md), [validated upserts](018-upserts.md), and [positional writes with array filters](020-positional-updates.md). Update pipelines and replacements remain deferred. `$unset` still removes optional properties, not array slots; `$inc` now supports numeric array targets.

## Evidence

Compile-only tests cover eligible paths, codec capability propagation, immutable descendants/ancestors, removal markers, and every update API. Unit tests cover invalid operands, conflicts, defaults/codecs, and path restrictions. Disposable MongoDB tests in `tests/update-operators.integration.ts` use `mica_update_operators` to verify concurrent increments without preliminary reads, missing/null values, stored-result validation, projected before/after documents, batch updates, and preflight failures that send no writes.
